# v0.1 hardening and release checks

## Findings corrected

- Initial `astro check`: two TS2322 errors because pdf-lib output views used ArrayBufferLike where
  BlobPart requires ArrayBuffer. Outputs now copy into an ArrayBuffer-owned Uint8Array.
- File picker `accept` values were the only type restriction. Selection now checks non-empty inputs,
  size, MIME consistency and format signatures, then reports decode/parse/read errors.
- Resize allowed fractional, excessive and unbounded-area dimensions despite HTML limits.
  Both source and requested output dimensions now have explicit integer/side/area checks.
- An unsupported WebP encoder could silently return PNG while naming the download `.webp`.
  Output MIME is now verified; unsupported encoders report a useful error.
- Selection/reorder/settings could change while work was running, producing stale or misnamed results.
  Controls now lock while work runs and old results are invalidated before new work/settings.
- Temporary result URLs survived selection changes, failures and page exit. All result invalidations
  now remove href/src and revoke URLs. Image resources/canvases are released in cleanup paths.
- Split retained duplicate PDF buffers and accepted empty comma entries. It now retains one parsed
  document, validates ranges before copying pages, preserves requested order and caps repetitions.
- PDF order arrows lacked accessible names; re-rendering lost keyboard focus. Named controls retain
  focus, have 44px touch targets, and preserve disabled order boundaries after processing.
- Long status/filenames could strain narrow layouts. Wrapping/min-width rules and reduced-motion
  support were added without a visual redesign. Each tool now links to related tools.
- No lockfile existed; CI used `npm install` and an incorrectly escaped network grep. Installs now
  use a committed lockfile and CI uses the same source-audit script as local verification.
- Hashed asset cache path was `/assets/*` instead of `/_astro/*`. Corrected, with a restrictive CSP
  and explicit JSON-LD escaping. No ads/analytics/CMP code was added.

## Automated coverage

Run the commands in README after `npm ci`. Pure validation tests exercise malformed/out-of-bounds
PDF ranges, dimensions, signatures, MIME mismatches, empty/oversized/unreadable inputs, corrupt PDFs
and readable PDF outputs. Browser tests run the built static pages with production CSP in desktop
Chromium, Pixel/Android Chromium emulation and iPhone/WebKit emulation. They cover all five tools,
download signatures and PDF page order, invalid-input recovery, stale downloads, Blob URL cleanup,
encoder fallback/failure, control locking, labels/focus and 320–768px overflow checks.

All fixtures are synthetic. No personal files, screenshots, traces, previews or file-derived values
are sent to external services. Test browser downloads stay on the local test machine.

## Manual release checklist

1. On physical Android Chrome and iPhone Safari, select files using the OS picker, process and save
   outputs using the browser's download/share UI. Open each result in an independent viewer.
2. Try JPG/PNG/WebP images, transparency, EXIF rotation, very tall images and large camera photos.
   Compare orientation, dimensions, quality, JPEG white background and single-frame animation behavior.
3. Merge PDFs, reorder/remove entries using touch and keyboard, then inspect page order. Extract
   ascending/descending ranges and repetitions. Try a password-protected and damaged PDF.
4. Try reading a deleted/unavailable device/cloud-provider file. Errors must be useful and allow retry.
5. Check with VoiceOver/TalkBack and keyboard: labels, focus, range errors, status announcements,
   reorder buttons, result links and the skip link. Also check 200% zoom and large OS text.
6. Observe Network while selecting, processing and downloading synthetic files: no HTTP requests
   should be triggered by file operations. Check that disabled controls prevent selection changes.
7. Set the real `PUBLIC_SITE_URL`, rebuild and deploy `dist` to Cloudflare Pages. Check canonical,
   robots, sitemap, HTTPS, redirects, 404 behavior, `_headers` CSP and `/_astro/*` cache headers.
   Leave host analytics, script injection, ads and CMP disabled.

## Remaining limitations

Emulation does not reproduce physical phone memory pressure, camera/OS pickers, Safari download UI,
screen readers or thermal performance. Browser decoders allocate before dimensions can be checked;
complex PDFs allocate during parsing. Files below limits can still exceed a device's available memory.
Processing runs on the main thread and can briefly block on complex files. Metadata/color profiles,
animated images, PDF forms/bookmarks/signatures and interactive features may change or be lost.
Keep originals and inspect outputs. This hardening does not constitute a public deployment.

## Verified local results (2026-10-31, America/Mexico_City)

Test environment: Node 24.22.1 and npm 12.2.1 on Windows.

- `npm ci --no-audit --no-fund`: passed, 278 packages installed from the lockfile.
- `npm run check`: passed, 31 files checked, zero errors/warnings/hints.
- `npm run build`: passed, static output in `dist`, 10 HTML pages plus robots/sitemap.
- `npm test`: 8 passed.
- `npm run test:browser`: 69 passed (23 per desktop Chromium, Android Chromium and iPhone WebKit profile).
- `npm run audit:privacy`: passed. The four requested network primitives also had no matches in built client JS.
- `git diff --check`: passed.
- Visual inspection at 320px confirmed resize controls and the corrected long-name PDF list fit.

Chromium exercises sequential Tab navigation. Mobile WebKit emulation checks focus rendering directly;
iOS Full Keyboard Access and screen-reader behavior require a physical-device check.
